## 一、线上版和 `docs/` 里那两个文件的关系

`docs/demo-report.html` 与 `docs/prototype-v2.html` 是**评审产物**：它们要能逐态巡检、要能切主题、要能一键跳到第 9 个界面。这些装置对访客是噪音——访客只想知道「这产品怎么用」。

所以线上版不是把 `docs/` 直接传上去，而是派生一份：

| 文件 | 来源 | 处理 |
| --- | --- | --- |
| `web/index.html` | 手写 | 入口页：一句主张 + 两个入口 + 三步玩法 + 演示声明 |
| `web/ledger.html` | `docs/demo-report.html` | 只改互链（`prototype-v2.html` → `plan.html`），其余原样 |
| `web/plan.html` | `docs/prototype-v2.html` | 摘评审装置、改互链、补玩法列与声明 |

派生脚本：`scripts/build-site.mjs`。**`docs/` 只读**，脚本对源文件不做任何写入。

任何一处标记找不到，脚本抛错退出——宁可构建失败，也不静默产出一个还带着评审面板的站点。

## 二、线上版摘掉了什么，留下了什么

### 摘掉（非核心操作，评审专用）

| 元素 | 为什么摘 |
| --- | --- |
| 右侧「直达界面」9 态跳板 | 评审用来逐屏巡检；访客跳过去只会看到没有上下文的孤立界面 |
| 右侧「场景模拟」面板 | 同上。其中「提交时售罄」在 demo 数据下 `PLAN.degrade` 为 `null`，点了会照常下单——留在线上是误导 |
| 右侧「当前状态 / 事件日志」 | 调试信息，访客看不懂也不需要 |
| 顶栏「浅色 / 深色」 | 展示用开关，与产品流程无关 |
| 顶栏「重置原型」 | 脚手架按钮；访客想重来有「再来一单」 |
| 手机下方 `S1 · 方案卡 · 合单主态` 状态标签 | 评审口径的状态编号，访客不需要 |

### 留下（核心流程，一步不少）

| 步骤 | 入口 | 断言 |
| --- | --- | --- |
| 选买法（合单 / 拆单 / 买卡） | 方案卡上的卡片 | `收银台` 前不变 |
| 切时间区间 | 页内 7 / 30 / 90 天 / 全部 | 金额与「再省」即时重算 |
| 生成待支付订单 | 底部主按钮 | 进入 `pay` 屏 |
| 支付 | 待支付页 → 收银台弹层 → 确认支付 | 进入 `success` 屏，给出取餐码 |
| 取餐码 / 再来一单 | 成功页 | 回到 `plan` |
| 撤销订单（二次确认） | 待支付页「撤销订单」→「确认撤销」 | 回到 `plan`，订单失效 |
| 支付中途退出（分支） | 底部默认折叠的「看一个分支」 | 进入 `fail` 屏，订单仍待支付 |

**为什么保留一个折叠分支**：`abort` 这条分支展示的是「支付回调不返回」时产品怎么兜底，是这套设计的一部分。做成默认折叠，主界面干净，需要时仍在。

### 补了一列「怎么玩」

右栏摘掉后，桌面上只剩一部 390px 宽的手机孤零零居中，左右各空一大片。补一列 248px 的玩法说明（`site-guide`，≤1000px 时隐藏）：
既把版面撑住，也让第一次进来的人知道该点哪里——这是"顺畅完成任务"的一部分，不是装饰。

## 三、一个必须记住的坑：面板摘掉后点击流会断

`renderLog()` 与 `renderPanel()` 会往侧栏节点写内容。侧栏被摘掉后这两个函数拿到的都是 `null`，直接抛 `TypeError`，表现为**点「生成订单」什么都不发生**——但控制台之外看不出来。

构建脚本里的 `guardPanelless()` 给这两个函数补了空值保护，并在源模板结构变化时抛错提醒重新定位。

这也说明线上版不能只靠肉眼验收：`verify:site` 里每一步都断言**屏幕真的切过去了**，而不是断言"点了没报错"。

## 四、怎么改、怎么重新发布

```bash
npm run build:site      # 从 docs/ 重新派生 web/（改了 docs/ 或 build-site.mjs 后必跑）
npm run verify:site     # 站点版回归：结构 + 全流程点击 + 零控制台异常
npm run audit:site      # WCAG AA 对比度审计
```

改完 `web/` 后重新发布，指向同一目录即可（分享链接不变）：

- 发布目录：`D:/PROJECT/mcd-ledger/web`
- 入口页：`index.html`

**注意**：分享链接带 `?sharecode=`，首次访问会种下 `__wb_rsc` Cookie，站内相对跳转靠它放行。所以站内链接一律写成相对路径（`plan.html`），不要把 sharecode 写进链接——重新发布后 code 可能变化。
