# 原型样式修复 v2.1 · 上边距与深色卡片辨识度

> 范围：`docs/prototype-v2.html` + `docs/tokens.css`
> 覆盖：8 个界面状态（S1–S8）× 浅色 / 深色 = 16 个页面面
> 结果：自动核查 **116/116 通过**，对比度审计 **0 处低于 AA**，控制台无异常

---

## 一、问题 1：上边距不足，阴影压住首张卡片（两主题均有）

### 根因（不是"阴影太重"，是两个结构问题叠加）

1. **导航下缘的渐隐带画在了内容之上。**
   `.navrow::after` 是一条 `bottom:-12px; height:12px` 的渐变条，
   从导航底边向**下**延伸 12px，压在正文上。
2. **正文与导航之间没有任何间距。**
   `.scr-body` 的 `padding-top` 为 `0`，导航又是 `.scr-body` 的第一个子元素，
   于是首张卡片顶边与导航底边**完全重合**（实测 `gap = 0`）。
   12px 的渐隐带整段落在卡片顶部 —— 卡片的圆角、1px 描边和前 12px 内容全部被灰带糊掉。

> 这也是为什么"所有页面都有"：间距来自容器，而 5 个屏的正文都挂在同一个容器上。
> 顺带一个隐患：导航是 `position:sticky` 撑在滚动容器内部的，滚动时它会遮住内容顶部。

### 修改方案

| 层 | 改动 | 前 → 后 |
|---|---|---|
| 结构 | 导航从滚动容器 `.scr-body` 里移出，成为 `.scr` 的固定子项（flex 子项，`position:relative`） | 导航在滚动区内部、sticky → 导航在滚动区**外部**，内容只在它下方滚动 |
| 间距 | 新增 token `--gutter-top`，落在 `.scr-body` 的 `padding-top` | `padding-top: 0` → `12px` |
| 间距 | 新增 token `--fade-nav`，渐隐带高度收到小于呼吸位 | `12px` → `9px`（12 − 9 = 3px 净空） |
| 尺寸 | 导航行高度等量回收，总高不变 | `46px` → `36px`（36 + 12 = 48，净增 2px） |
| 阴影 | 浅色卡片阴影改为"只向下"的双层投影 | `0 1px 2px rgba(26,22,20,.04)` → `0 1px 2px rgba(26,22,20,.05), 0 10px 22px -16px rgba(26,22,20,.20)` |

**为什么"移出滚动容器"而不是继续加 padding：**
只要导航还在滚动容器内部，它的背景/渐隐就总有和内容重叠的机会；移出后
"内容的最顶端"和"导航的最底端"是两个不相交的盒子，首屏被压住这类问题
在结构上不可能再发生，滚动时内容也只是被裁切在导航下沿，不会钻到标题底下。

### 涉及元素

`.scr` / `.scr-body` / `.navrow` / `.navrow::after` / 每屏首个内容块
（`.intent`、`.banner`、`.card.amount-card`、`.row`、`.card.big-card`）

### 预期效果

- 8 屏在任何滚动位置都保持"导航 → 12px 空白 → 首张卡片"的关系，卡片圆角、描边、顶部内容完整可见；
- 渐隐带只作用于滚动中的内容（滚动时内容在 9px 内渐隐），静止时落在空白呼吸位上；
- 每屏正文净高度只减少 2px：S1 余 1.7px、S5 余 7.3px，均仍在首屏内完整显示，无需滚动。

## 二、问题 2：深色卡片辨识度低，边框几乎不可见

### 根因（三个值同时"贴地"）

| 项 | 旧值 | 问题 |
|---|---|---|
| 卡面 `--surface` | `#111113` | 与底色 `#09090A` 只差 2 级，卡面与背景几乎同色 |
| 描边 `--border` | `rgba(255,255,255,.075)` | 压在 `#111113` 上合成 `#232326`，与卡面 **1.18:1**，肉眼等于没画 |
| 阴影 `--shadow-card` | 只有 `inset 0 1px 0 rgba(255,255,255,.03)` | 1px × 3% 白，深色下读不出"卡片浮起"的层 |

另外一个隐性问题：深色的 `--border-2`（分割线）比 `--border`（外描边）**更强**，
和浅色正好相反 —— 同一套组件在两个主题里的层级逻辑不一致。

### 修改方案：把深色重排成四级明度梯子

| Token | 旧 | 新 | 说明 |
|---|---|---|---|
| `--app-bg` | `#09090a` | `#09090a` | 底色不动（与 demo 同源） |
| `--surface` | `#111113` | `#17171b` | 卡片，比底色亮出可读的一档 |
| `--surface-2` | `#151518` | `#202026` | 卡内次级块（合计条、提示条） |
| `--surface-3` | `#0c0c0e` | `#0e0e11` | 卡内凹槽（序号圆、失效图标底） |
| `--intent-bg` | `#17171a` | `#232329` | 意图条，保证与卡片再区分一档 |
| `--brand-soft` / `--surface-tint` | `#1e1414` | `#2c1a19` | 选中态红调底，随新卡面重新配平 |
| `--bezel` | `#151518` | `#1a1a20` | 手机中框环 |
| `--border` | `rgba(255,255,255,.075)` | `rgba(255,255,255,.14)` | 外描边，合成 `#37373B`，与卡面 **1.51:1** |
| `--border-2` | `rgba(255,255,255,.14)` | `rgba(255,255,255,.09)` | 分割线，**弱于**外描边（与浅色层级对齐） |
| `--border-strong` | `rgba(255,255,255,.22)` | `rgba(255,255,255,.26)` | 次按钮 / 单选圈 |
| `--shadow-card` | `inset 0 1px 0 rgba(255,255,255,.03)` | `inset 0 1px 0 rgba(255,255,255,.05), 0 8px 20px -14px rgba(0,0,0,.9)` | 内高光立边 + 投影兜底 |

**为什么不是继续加粗描边就够了：** 深色界面里"卡片能读出来"靠的是
面（surface 抬升）+ 线（描边）+ 光（顶部内高光）三件事同时成立；
只把描边从 7.5% 加到 30% 会得到一圈"硬灰框"，卡片反而像表格。

### 卡片面统一（两个主题共用）

之前只有 `.card` 带 `box-shadow`，`ord-card` / `payway` / `qr-card` / `big-card` /
`store-row` / `notice` / `gcard` 都是"裸描边"，深色下这些块读不出边界，
和 `.card` 也不像一个系统。现统一为一条规则：

```css
.card,.big-card,.ord-card,.payway,.qr-card,.store-row,.notice,.gcard{box-shadow:var(--shadow-card)}
```

浅色侧同一规则生效（阴影极轻，不改变观感），保证两主题"表面 + 描边 + 阴影"三件套结构一致。

### 涉及元素

`.card` `.big-card` `.ord-card` `.payway` `.qr-card` `.store-row` `.notice` `.gcard`
`.intent` `.timer` `.chip-*` `.scr-foot` `.sheet` `.toast` `.device` `.pcard`（侧栏）

### 预期效果

- 卡片与底色、卡片与卡片之间都有可读边界；分割线仍然比外框弱，不抢层次；
- 意图条 / 选中态 / 次级块各自成一个明度台阶，不再糊成一片黑；
- 抬高卡面后，卡面内的文字对比度全部上升（`#F3EFE6` on `#17171B` 由 17.3:1 升到更高），没有换取可读性的代价。

## 三、验证方式

| 手段 | 脚本 | 结果 |
|---|---|---|
| 真实 Chrome 点击流 + 断言 | `out/verify-proto.mjs` | **116/116 通过**，含新增 18 项：8 屏 × 2 主题的"上边距 ≥ 渐隐带 + 导航不在滚动容器内"、深色描边 14%、卡面 `#17171b`、卡片内高光 |
| 对比度审计（8 屏 + 弹层 + toast × 2 主题） | `out/audit-contrast.mjs` | **0 处低于 AA** |
| 几何量测 | `out/probe-v2.mjs` | `padding-top 12px` / `gap 12` / `fade 9` / 卡面 `rgb(23,23,27)` / 描边 `rgba(255,255,255,.14)` |
| 视觉复核 | `out/p-s1..s8-*.png`、`out/after-*.png` | 逐屏浅/深截图确认首屏卡片顶边完整、滚动态渐隐正常 |

回归口径：上边距不变式是 `gap ≥ fade`，任何一个新屏只要把内容塞进 `.scr-body` 就自动成立；
深色不变式是 `--border ≥ 0.12` 且 `--border-2 < --border`。
